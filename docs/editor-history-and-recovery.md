# 项目撤销、重做与恢复副本

Editor 的表单、Blockly 和 Code 共用 C++ Author 会话中的项目操作历史。工具栏的撤销、
重做按钮操作这份历史；编辑区的 `Ctrl/Cmd+Z`、`Ctrl/Cmd+Shift+Z` 和 `Ctrl+Y` 使用相同入口。
输入框正在编辑文字时，快捷键保留文本自身的撤销行为。工具栏的项目撤销会先提交当前
有效草稿；语法错误或尚未应用的 Code 草稿会阻止项目撤销，避免覆盖草稿。

## 历史语义

- 一次成功且实际改变数据的 Backend 命令形成一个记录，包括批量节点编辑、场景内容
  替换、页面样式和资源导入、重命名、逻辑删除。失败命令和 no-op 不消耗历史。
- Undo/Redo 恢复完整 Author 聚合及私有资源元数据，节点和资源 ID 保持不变。
- 历史仅存于当前窗口会话，最多 100 条、序列化快照合计最多 64 MiB，以先达到者为准。
  达到预算后丢弃最旧记录；单个快照超出预算时无法保留该步历史。
- 撤销后的新修改清除重做分支。保存保留历史；新建、打开工程和恢复副本建立新的历史。
- `revision` 对每次实际变更持续递增；`documentRevision` 标识当前历史状态。
  Main 将 `documentRevision` 与最近成功发布到用户目录的状态比较，因此撤销回保存点
  会清除脏标记，重做离开保存点会重新标记。私有 checkpoint 不算用户保存。
- Blockly 的独立事件撤销栈关闭，避免与项目历史产生两套状态；项目操作使用顶部按钮
  或编辑区快捷键。草稿中的文本编辑仍遵循输入框语义。
- 资源只做逻辑删除，已有文件保留。Main 缓存当前会话验证过的资源路径映射，并在
  Undo/Redo 时重建活动资源集合、轮换预览令牌；删除后的旧 URL 不重新生效。

## 恢复副本

`ProjectRecoveryService` 在 Electron `userData/project-recovery/<会话 UUID>/` 保存独立副本。
目录内包含标准 `project.vn.json`、独立的 `assets/` 和惰性的 `drafts.json` 文本草稿。
备份不会改写用户保存的工程，不在作者格式中增加字段。

成功的项目/资源修改在同一个 Main 文件事务内更新恢复副本。先复制并同步媒体，再校验
完整快照，最后原子替换 manifest。媒体 ID 集合和源目录不变时，不重复复制媒体。
备份失败不撤销已成功的作者修改，保留已发布的有效副本，并在工具栏提示手动保存。

表单中的对白草稿、项目名和 Code 原文在停止输入约 750 ms 后独立提交备份。
Code 草稿同时保留 `baseSource`；恢复后仍走正常语法解析、冲突检测和应用流程，
不会自动执行或强制写入 Author 模型。草稿请求限制为 100 个 Code 草稿、总计 2 MiB，
Renderer 不提供本机路径。尚未提交的 Blockly 字段、场景名称、图片缩放等临时界面状态
不在文本草稿备份范围；已提交到项目的修改均在恢复快照中。

## 用户流程

1. 再次启动时，Editor 按更新时间提供此前窗口的恢复副本，可恢复、查看下一个、删除或稍后处理。
2. 工具栏“恢复”和原生菜单“恢复未保存的项目”也能打开恢复入口，包括本窗口的最新副本。
3. 正在其他窗口中使用的恢复副本不会出现在选择中。
4. 恢复先复制到新的临时工作区并校验，再打开为**未保存工程**。随后保存时选择新目录，
   不自动覆盖原工程。恢复副本在成功手动保存前继续保留。
5. 后端独立崩溃后，如果重新连接发现新的空项目，Main 先解除旧保存路径的绑定，再提供恢复。
6. 正常保存成功后清理对应恢复副本；关闭未保存窗口仍保留副本。空白未编辑窗口不产生副本。

恢复保证截止到最近一次成功 checkpoint；突然断电或进程退出前尚未传送的按键不能保证恢复。
恢复后不延续崩溃前的 Undo/Redo 栈。

## 实现与验证

- `engine/src/backend/backend.cpp`：权威历史、`history.undo` / `history.redo` 与 Main 专用
  `project.checkpoint`。Author v22 和 Runtime/Snapshot 格式保持兼容。
- `apps/editor/src/main/project/ProjectRecoveryService.ts`：恢复副本、资源复制、草稿与恢复流程。
- `ProjectFileSession.ts`：用户保存点与历史状态身份；`AssetPreviewService.ts`：历史资源预览。
- `useEngineProject.ts` / `App.tsx`：命令队列、三视图草稿边界、快捷键与文本草稿恢复。

验证覆盖 Backend 的 no-op、失败、分支、保存点、历史容量和资源恢复；真实 C++ 集成测试
覆盖停止后端并删除临时工作区后的恢复、媒体再次发布、无效 Code 草稿保留、备份失败回退、
窗口隔离和符号链接拒绝。UI 测试覆盖三模式在撤销前提交草稿及提交失败时阻止撤销。
